# 需求评审

## 目标

建立覆盖 Harness Desktop 全应用的统一视觉与交互体系，让用户在不同模块间切换时获得一致的页面层级、控件反馈、状态表达和动画节奏，同时提升界面精致度、可读性和窄窗口可用性。

## 范围

- 统一应用壳层：Sidebar、品牌区、工作区标题栏、页面背景和内容容器。
- 建立设计令牌：颜色、字体、间距、圆角、边框、阴影、层级和动效时长/缓动。
- 统一通用组件：按钮、图标按钮、输入框、选择器、卡片、面板、表格、标签、提示、空状态、抽屉和滚动条。
- 覆盖 Runs、Workflow、Terminal、Artifacts、Gates、Knowledge、Recovery、Settings 等主要页面。
- 添加克制的页面进入、卡片悬停、导航状态、抽屉和加载/状态切换动画。
- 增加窄屏响应式布局和 `prefers-reduced-motion` 支持。
- 保留各模块语义差异：Terminal 继续使用深色工作区；成功、警告、失败和信息状态保持可辨识。

## 非目标

- 不改 Runtime、IPC、API、数据模型、业务流程、权限规则和 Harness 协议。
- 不重新设计产品信息架构或新增业务功能。
- 不替换现有图标库、引入大型 UI 框架或新增网络字体依赖。
- 不回退或重写当前工作区中已有的 Runs、Gates、Knowledge、Terminal、Settings 等功能实现。
- 不添加持续漂浮、粒子背景或影响阅读和性能的高强度动画。

## 验收标准

- [ ] 应用壳层具有一致的深色侧栏、明亮工作区、清晰活动导航指示和统一页面标题层级。
  - 验证方式：检查 App、Sidebar 及主要路由页面，确认共享视觉变量和壳层样式生效。
- [ ] 颜色、圆角、边框、阴影、间距和动效由集中设计令牌驱动，主要模块不再各自使用明显冲突的基础视觉值。
  - 验证方式：源码测试检查关键令牌存在，并抽查全局、Runs、Gates 等样式引用统一变量。
- [ ] 按钮、表单、卡片、表格、状态标签、提示和空状态在不同页面具有一致的默认、悬停、聚焦、禁用和危险状态。
  - 验证方式：检查通用选择器与页面截图/本地运行效果；键盘聚焦时存在清晰 focus-visible 样式。
- [ ] Runs、Workflow、Artifacts、Gates、Knowledge、Recovery、Settings 页面在常规桌面宽度下无明显错位、遮挡或不必要大片留白。
  - 验证方式：本地运行后逐页检查关键页面；构建和现有组件测试通过。
- [ ] Terminal 的输入区、滚动区和内容尺寸不受页面进入或卡片动画影响，中文 IME、粘贴和滚动相关实现保持不变。
  - 验证方式：Terminal 现有测试通过，并确认仅修改外观样式而不更改终端会话逻辑。
- [ ] 窄窗口下侧栏、页头、双栏/多栏内容能够折叠或换行，不产生横向内容截断。
  - 验证方式：样式中包含明确的窄屏断点，并对主要布局进行静态检查或本地窗口缩放检查。
- [ ] 页面与状态动画时长克制，用户启用减少动态效果后动画和过渡被关闭或显著缩短。
  - 验证方式：源码测试检查 `prefers-reduced-motion: reduce`，并确认全局动效变量和关键动画使用统一时长。
- [ ] Renderer 类型检查、单元测试和生产构建均成功。
  - 验证方式：依次执行 renderer typecheck、test、build，退出码均为 0。

## 开放问题

- 无阻塞开放问题。视觉方向、覆盖模块、动画强度、响应式要求和业务边界均已由用户确认。

## 风险备注

- 全局 CSS 的选择器覆盖可能影响已有模块，需避免高权重和破坏性重置。
- 独立模块 CSS 中可能存在硬编码颜色，应通过变量映射逐步统一而非整页重写。
- Terminal、Workflow Canvas 等尺寸敏感区域应避免 transform 作用于其核心内容容器。
- 工作区存在大量未提交功能改动，实施必须保持小范围、可审阅，不做格式化全仓重写。

## G1 结论

需求目标、范围、非目标和可观察验收标准明确，无阻塞问题。`G1_REQUIREMENTS = PASS`。
