# 需求评审

## 目标

主界面使用“安全直接合并、主项目、任务代码、保存为版本、临时保存”等普通语言，避免要求用户理解 Fast-forward、HEAD、Index、Ahead/Behind。

## 验收标准

- [ ] 合并向导主要区域不出现 `Fast-forward`、`FF-only`、`HEAD`、`Index`、`Run-only commits`、`Target-only commits`。
- [ ] 可合并状态解释不会产生额外合并记录，也不会覆盖主项目的新修改。
- [ ] 不可合并状态明确告诉用户软件已停止、代码未改变以及下一步操作。
- [ ] 专业 Git 信息仍可在“技术详情”中查看。
- [ ] 类型检查、测试和构建通过。

## 非目标

- 修改 Runtime 数据字段或 Git 命令。
- 自动处理分支分叉或冲突。
